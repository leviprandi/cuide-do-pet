# Skills Quick Reference

## Purpose

Short operational guide to choose the right skill quickly for the current phase, without scanning the full catalog first.

## Current Project Phase

- Local-first MVP
- Frontend: Next.js
- Backend: NestJS
- Database: PostgreSQL local
- ORM: Prisma
- AI provider planned later: MiniMax
- Current focus: environment setup, healthcheck, Prisma setup, initial schema, pets module

## Core Selection Rules

1. Select only one primary skill per task.
2. Use a second skill only when it directly supports the same task.
3. Never use fallbacks that hide issues or errors.

## When To Use (Priority Skills Now)

### best-practices
Use when implementing backend or frontend features, refactoring, defining structure, or improving code quality and technical discipline.

### develop-frontend
Use when working on UI behavior, layout, responsiveness, and visible states (loading, empty, success, error).

### security-threat-checklist
Use when touching auth, secrets, environment variables, public endpoints, provider integrations, or permission-sensitive logic.

### playwright
Use when validating browser flows end to end with automated checks.

### playwright-interactive
Use when debugging UI behavior interactively in real browser sessions.

## Not Priority Now

- Deploy-oriented skills (for example vercel-deploy, render-deploy, cloudflare-deploy)
- Web3-oriented skills (for example web2-wallet-auth, ponder-indexer-events, upgradeability-governance)

Use these only when project scope explicitly enters deployment or web3 requirements.
